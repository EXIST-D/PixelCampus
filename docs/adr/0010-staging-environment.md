# 0010 测试环境：同机、同域名真实 HTTPS、隐藏路径、数据隔离

- 状态：已采纳
- 日期：2026-11-10

## 背景
改完代码要么只在本机验证（单人、localhost、没有真实 HTTPS / 手机 / 多人环境），要么直接部署到有真实玩家的正式环境。需要一个和正式环境同构、可随时部署、多人 / 手机联测的测试环境，并为后续「协作者先在测试环境验证、主人确认后上线」做准备。

## 决定
- 放在**正式服务器上**再起一个独立实例（不用另一台机器），沿用同一域名和 HTTPS 证书，手机联测最像线上；
- **访问控制 = 隐藏路径**（含随机串、不公开、`noindex`）；
- **数据完全隔离**：独立系统用户、数据目录、端口（8788）、管理员口令；`InaccessiblePaths` 让测试进程看不到正式数据；默认空数据，不拷真实玩家档案；
- 资源上限：内存 200MB、最多 30 人；
- 部署入口显式：`npm run deploy`（正式，路径 / 目录 / 服务 / 端口写死）与 `npm run deploy:test`（读私有的测试配置，不 bake）；测试构建带 `VITE_ENV=test`，页面显示「测试环境」标记；
- 正式环境的部署权不变（ADR 0008）；测试环境的部署可以以后委托给协作者（受限部署密钥）。

## 后果
- 正式服务器多了一个进程（约 45~80MB）和一段 nginx 配置（只新增，不改已有）；
- 同机资源竞争可控（有上限）；测试只验证功能，不验证大并发；
- 隐藏路径是共享秘密，泄露要换路径；
- 需要保证测试数据不使用真实玩家信息。

## 备选方案
- 悉尼备用机作测试环境（物理隔离更安全，但国内延迟高、没有同一张网的真实 HTTPS，被否）；
- 口令 / IP 白名单（口令要改 nginx 基本认证、白名单对手机网络不友好，隐藏路径最简单，被选）。
