# 0012 服务端放在独立的私有仓库，协作者加入该仓库提 PR

- 状态：已采纳（细化 [ADR 0001](0001-public-private-split.md) 的实现方式）
- 日期：2026-11-10

## 背景
ADR 0001 决定服务端不进公开仓库。最初的做法是主人本机用一个「私有备份仓库」跟踪同一工作目录里的 `server/`、`deploy/`、词库、私有文档等：能备份，但**不适合协作**——GitHub 权限按整个仓库给，把协作者加进去会同时暴露部署脚本、服务器信息、词库原文和私有文档；用压缩包 + 补丁发给协作者则没有版本记录、会过期、无法撤权。

## 决定
- 新建独立私有仓库 **`PixelCampus-server`**：服务端代码、服务端测试、敏感词引擎、协作者用的测试环境部署脚本、CI。**不含**正式环境部署脚本、服务器信息、词库原文、玩家数据、私有文档；
- 保留服务端历史（旧仓库 + 私有备份库共 57 条提交，作者与日期不变）；
- 仓库克隆到公开仓库的 `server/` 目录里使用（公开仓库忽略 `server/`）；服务端测试在 `server/tests/`，公开仓库的 vitest 配置额外包含它；
- 协作者加为该仓库的协作者（**写权限**），**开分支 + PR**；免费版私有仓库不能强制保护 `main`，靠约定，并且主人只 pull 审阅过的提交、线上部署用主人本机的代码，所以别人推 `main` 不会直接影响线上；
- CI 在服务端仓库里：检出公开仓库（默认 `main`，PR 描述里写 `Public-Branch: <用户名>/PixelCampus@<分支>` 可指定配套的公开分支）+ 服务端，跑类型检查和全部测试；
- 主人个人的私有备份仓库继续备份 `deploy/`、词库、`docs/private/` 等**不对协作者开放**的内容，不再跟踪 `server/`；
- 正式环境部署权不变（ADR 0008）；协作者部署到测试环境走受限账号（ADR 0011）。

## 后果
- 协作者有了正常的 git 流程（分支、PR、历史、可撤权）；不再需要压缩包和补丁；
- 能看到代码就能复制，只能靠信任和约定；写权限 + 免费版意味着 `main` 没有硬保护（主人审阅后才 pull 是实际的闸门，且要保留本地备份以防被强推）；
- 服务端和公开仓库要成对修改、成对合并，靠 PR 互相链接 + CI 的 `Public-Branch` 机制协调；
- 主人本机的 `server/` 变成独立 git 仓库，服务端改动在里面提交 / 推送。

## 备选方案
- 把协作者加进现有私有备份库（暴露部署与运维信息，被否）；压缩包 + 补丁（无历史、会过期，被否）；只读 + fork（更安全，但主人选择了写权限以减少摩擦）；git submodule（要求公开仓库记录私有仓库地址并绑定提交，被否）。
