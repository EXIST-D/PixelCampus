# 0011 协作者自助部署：受限账号 + 命令白名单 + 沙箱

- 状态：已采纳
- 日期：2026-11-10

## 背景
测试环境（[ADR 0010](0010-staging-environment.md)）已经有了，但只有主人能部署。服务端协作者改完代码后需要自己部署联测，又不能拿到服务器登录权限，更不能碰正式环境和同机其他服务。

## 决定
- 服务器上新增受限账号，每个协作者**自己的 SSH 密钥**一行；`restrict` + 强制命令，客户端想执行什么都被忽略，只认白名单：`deploy [code|full]`、`status`、`logs`、`rollback`、`reset`、`sethash`；
- 提权只靠一条 sudo 规则：以**固定参数**运行一个 root 所有、路径写死的控制脚本；
- 上传校验（大小、路径、链接、顶层只能是 `dist/` 和 `server.mjs`、压缩炸弹）、同时只允许一个部署、保留最近 3 个版本、新版本起不来自动回滚；
- 测试服务沙箱：不能访问外网（只放行回环）、看不到正式数据 / nginx / 其他服务的文件；
- 默认 `code` 模式只传代码（几 MB），地图 / 图集等生成资源由主人部署，改了资源才用 `full`；
- 正式环境的部署权不变（[ADR 0008](0008-deploy-by-owner.md)）；撤销协作者 = 删一行公钥。

## 后果
- 协作者可以在沙箱里运行任意服务端代码，所以只给**受信任**的人；
- 每人一把密钥，可单独撤销，操作有日志；
- 测试环境是共用的一个实例，同一时间只部署一个分支；
- 脚本很小、可审计，但仍要在改动时重新做越权验证。

## 备选方案
- 给协作者 root / sudo（越权，被否）；共用一个密钥（无法单独撤销，被否）；在服务器上构建（内存小、要放源码，被否）；GitHub Actions 自动部署（可作为以后的增强，仍用同一个受限账号）。
