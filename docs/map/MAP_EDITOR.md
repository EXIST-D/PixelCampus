# 地图编辑器

> 用户（主人）自己动手微调地图的小工具：在编译好的当前地图上涂地面、摆/擦树和小品，保存成一个"手动层"文件，由 Claude 读取、生成、测试、提交、推送。省去"说一句改一句"的来回。

## 怎么用（主人）
```bash
npm run editor        # 启动，然后用浏览器（Chrome/Safari 都行）打开 http://127.0.0.1:5174
```
1. 需要先有生成好的地图（新克隆的仓库先 `npm run assets`，约 2 分钟）。
2. 左边选工具，右边选材质/物件，在地图上操作；`Ctrl+Z` 撤销，`Ctrl+S` 保存。
3. 想看真正的游戏画面：点「**保存并生成预览**」（十几秒），生成完地图会自动刷新——这时看到的就是游戏里的样子。（预览会先生成 PNG 图集，再自动转成游戏用的 WebP；如果你是在命令行里手动 `npm run assets:world`，要再跑一次 `npm run assets:webp`，否则游戏里的新建筑会显示成乱拼的碎片。）
4. 改好了，**保存**，然后告诉 Claude "编辑器改好了"。Claude 会看 `data/campus/manual.json` 的变化、重新生成、跑测试、提交并推送（部署仍然只在你说"部署"时做）。

| 工具（快捷键） | 作用 |
|---|---|
| 选择（V） | 点选你加的东西或**地图上已有的物件**；拖动移动、拖白点改大小/顶点、Delete 删除。已有的树/路灯等可以删除，也能拖到新位置（= 擦掉原来的、摆一个新的） |
| 涂矩形（R）/ 涂椭圆（E）/ 涂多边形（P） | 选一种地面材质涂上去（盖在原来的地面上） |
| 画路（L） | 起点按下、拖到终点松开，画一段**横平竖直、方头**的路（宽度可设），不会有圆头 |
| 斜路/折线路（K） | 选材质和路宽，**依次点顶点**画斜向/拐弯的路，双击或 Enter 完成，Backspace 退回一个点，Esc 取消。方向默认锁在 15° 的倍数（右侧可改 45°/横平竖直/自由，按住 Shift 临时反转）；**两端默认切平**（垂直于路方向截断，不冒半圆），拐点是圆的不留缺口；沥青路还能加车道线（虚中线/边线/双黄线）。完成后用「选择」拖白点改路线、改宽度 |
| 运动场（F） | 选足球场 / 篮球场 / 网球场 / 田径场（跑道），拖一个矩形（只点一下 = 默认大小）：自动铺好**地面、白线、球门/篮架、围栏（留缺口）、四角灯杆**。建好后自动切到「选择」，拖白点改大小、拖动整体移动，右侧改种类、围栏/缺口方向/灯杆/球门；球门和篮架放在长边两头，横着的球场长轴沿横向 |
| 围栏围墙（W） | 依次点顶点，双击或 Enter 完成：铁栏杆或砖墙（砖柱间隔可设）；方向默认锁 90°；路口自动留口（可勾「忽略地面」）；斜线会变成阶梯状的横竖段。完成后用「选择」拖白点 |
| 摆物件（O） | 点一下摆一个树/路灯/长椅/花坛等 |
| 连排摆（T） | 点起点、点终点，沿线按间距连排摆（行道树、路灯） |
| 改建筑（B） | 点一栋楼选中：**拖动 = 整栋移动**（按住 Shift 拖 = 只移动点中的那一段），**拖白点 = 改这一段的长/宽**；右侧可改名字、种类、风格、层数、屋面色、门牌，**接一段新的翼体**（向右/左/下/上接、复制此段）做出拐弯/L 形，删除一段/整栋，或还原成原来的 |
| 加门（D） | 点楼某一段的**南面边缘**加门（引擎里的门都开在翼体的南面）；拖门左右滑动；右侧可调门宽、设为正门（★）、去掉门。**红色 = 门前 1.5 格被别的楼/别段盖住了，走不进去** |
| 新建筑（N） | 在空地上拖一个矩形，新建一栋楼（先用现有素材：红砖、4 层、南面有门），建好后在「改建筑」里调整 |
| 擦除（X） | 拖一个矩形，擦掉范围内已有的物件（可选全部/只树/只小品）；校园商店、校园墙不会被擦。勾「连带去掉框内的蓝图图形」，整个落在框里的运动场地面/白线/围栏等也一并去掉（先清掉旧运动场再放新的） |

- 「跳到…」里有 2026-11-04 新增的片区（太极广场、图书馆西侧、两个荷塘、文法/管商、机械/信电、材料/矿测/地球、西操场、留学生公寓、一/二社区）。
- 2026-11-04 起荷塘（`12-`）、图书馆西侧花草地/水渠（`36-`）进「绿地」类，太极广场（`34-`）进「广场铺装」类，可以点选改/删；睡莲、小亭这类物件不进列表，用擦除或摆物件改。
- 坐标单位是"原 5 m 格"（和蓝图一致），默认吸附到 0.5 格（= 游戏里的 1 格 = 2.5 m）。右下角显示光标坐标。
- 右键拖动或按住空格拖动平移，滚轮缩放；顶部「跳到…」可以直接去某个地方。
- 「显示」里可以关掉地面/建筑/物件/网格，只看"我的改动"；左下角的「季节」只影响编辑器里的显示。
- 每次保存前会把旧文件备份到 `.cache/manual-backups/`（留最近 30 份）；没保存的修改也会存在浏览器里，下次打开会问要不要恢复。

## 部署之后会自动"并入"（让编辑器重新变干净）
`npm run deploy` 成功后会自动运行 `npm run bake`（`tools/editor/bake.ts`）：
- 把当时的 `manual.json` **作为新的一层追加到 `data/campus/baked.json`**（已并入基础地图的各层，编译时按顺序先于 manual.json 叠加，生成的地图和并入前**完全一样**——并入前后 `world.json` 逐字节相同）；
- 再把 `manual.json` **清空**。编辑器重新打开就是干净的：没有上一次部署的草图、改动列表和撤销痕迹，只加载真正在改的东西，也更快；
- 并入前的 `manual.json` 备份在 `.cache/manual-backups/`，git 历史里也有；
- **并入之后要提交 `baked.json` 和 `manual.json` 的变化**（Claude 部署完会顺手提交）。
- 编辑器开着的时候发生了并入：页面会提示"请刷新"，并且拒绝保存（否则会把已并入的改动又写回来）。旧的草稿也会作废。
- 并入后这些改动变成基础地图的一部分：编辑器里点选已有的楼/物件照样能改（会产生新的改动），只是看不到"上次的改动列表"了。
- 想手动并入：`npm run bake`；想让某一层失效：从 `baked.json` 的 `layers` 里删掉它（或 `git revert` 并入的那个提交）。

## 涂地面是"覆盖"还是"替换"？会不会越攒越冗余？
- **最终的地图里是替换**：地图每一格只有一种材质，后涂的直接改写这一格（盖在原来的材质上，原来的材质就没了）；不会"叠很多层"，游戏里的文件大小也不受影响。
- **数据里是按先后顺序记着每一笔**（`manual.json` 的 `shapes`，后面的盖前面的）。所以反复涂同一块地方，被完全盖住的旧笔画留在文件里就是纯冗余。
- **现在会自动整理**：保存时、部署并入（bake）时，会去掉**被后面的矩形完全盖住**的旧图形（一块盖住、几块拼起来盖住都算；椭圆/多边形/折线按外接矩形保守判断）、同一位置重复摆的同种物件、被更大擦除范围包住的擦除；并入各层时，后面的层盖住的前面层的图形也去掉。整理后画出来的地图**完全一样**（实测 `world.json` 逐字节相同）。
- 右侧「我的改动」里有「整理（可去掉 n 项冗余）」按钮，想随时整理就点它（可以 `Ctrl+Z` 撤销）。
- 先涂大块、后涂小块不算冗余（小块在大块上面，有贡献），不会被去掉；只被部分盖住的也保留。

## 手动层是什么（`data/campus/manual.json`）
编译（`tools/world/compile.ts`）把它放在**最后**处理，所以用户的决定总是优先：
- `shapes`：地面（rect/ellipse/poly），在所有蓝图地面画完之后再画，盖住下面的；
- `erase`：擦除范围，在所有自动种树/摆路灯/清理完成之后执行；
- `objects`、`rows`：手动摆的物件，同样在清理之后放，**不会被"路灯变稀""道路中间不放树"之类的自动规则去掉**，也不受门前保留区限制（用户说了算）。
格式、校验、沿线取点、精灵挑选都在 `src/shared/manual.ts`（编辑器、编译、测试共用）；测试 `tests/manual.test.ts`。

## 建筑怎么改的
- 一栋楼由几段**翼体**（矩形体量）拼成，L 形、回字形的楼就是几段拼在一起；编辑器里改的是**脚印**（楼实际立在地上的位置），不再做卫星斜视角的屋顶→脚印换算。
- 改过的楼整栋存进手动层的 `buildings`（同 id = 替换原来的；新 id = 新建筑；`delete` = 删掉原来的）；点「保存并生成预览」之前，改过的楼显示为红褐色的脚印草图（旧的建筑图先藏起来），生成后换成真正的建筑图。
- 建筑的图是按风格、层数、屋面色程序化生成的，所以"移动、改长度、加一段、改层数/风格"都能直接生成；斜着的翼体（全校只有 5 段）只能整段移动，不能改大小。
- **融合**：在「改建筑」里按住 Ctrl（Mac 用 ⌘）逐个点击要合并的楼（青色描边 = 已选），右侧填新名字，点「融合成一栋楼」：所有翼体并成一栋、位置不变，门保留（只留一个正门），其余几栋删掉；一栋楼最多 48 段翼体；可以 Ctrl+Z 撤销。
- **视角旋转**：顶栏「视角 ⟲ ⟳ 复位」，或按 `[` `]`（每次 15°）、`\` 复位、按住 Alt 滚动滚轮（每格 5°）。转的是整张画布，鼠标操作随之换算；文字保持正向，建筑图会跟着转（只是方便看，游戏里镜头不转）。
- 编辑器的建筑数据来自编译时导出的 `.cache/editor-buildings.json`：**改了地图/建筑数据后要先 `npm run assets:world`，编辑器才看得到最新的楼**（编辑器里点「保存并生成预览」会自动做这一步）。

## 编辑器为什么会快
- 生成的地图文件（几十 MB 的地面块）网址带版本号（地图生成时间），浏览器会一直缓存，**第二次打开几乎不用下载**；
- 地面块按离屏幕中心近的先加载、同时最多 6 张，没加载好的地方先垫一张整图缩略图，**不再是大片黑色**；
- 底图（地面 + 物件 + 建筑）缓存在离屏画布上，只有平移/缩放/旋转/切换图层时才重画；鼠标移动、选中只重画上面的叠加层。

## 运动场地、围栏围墙、斜路（2026-11-03）
- **运动场模板**（`manual.json` 的 `fields`）：一个矩形 + 种类，编译时由 `expandField()`（`src/shared/manual.ts`，编辑器预览和编译共用）展开成地面图形 + 白线 + 球门/篮架/灯杆 + 围栏段；展开后和手动涂的地面一样盖在蓝图之上。足球场按标准比例画禁区/球门区/中圈，篮球场有球篮区、三分线，网球场有网线/发球线，田径场是跑道形（两端半圆）塑胶外圈 + 红色跑道 + 分道线 + 草坪内场。
- **蓝图里已有的东西现在也能改**：编辑器右侧「显示」里勾「蓝图图形（可改）」和类别（运动场地 / 围栏围墙 / 道路 / 广场铺装 / 绿地），勾上的类别会画出细线轮廓。用「选择」点中后：
  - 拖动 / 拖白点 / 改数值 = **原位修改**（保存在 `bp.edit`，**保持原来的盖住与被盖顺序**，所以改了塑胶圈不会盖住跑道）；原位置显示灰色虚线，生成预览后才生效；
  - Delete = **去掉**（`bp.hide`，红色虚线；点选后可以「恢复」）；「蓝图图形全部恢复原样」一键还原；
  - 球门、篮架、看台、灯杆、体育中心大精灵是地图上的**物件**，直接用「选择」点中、拖动或删除（现在小品列表里也能摆这些，以及砖墙/铁栏/砖柱）。
- 蓝图条目的 id 是「文件名#序号:内容指纹」（`tools/world/blueprint-load.ts`）；蓝图文件里那一条改了，旧 id 自动失效（不会误伤别的条目）。编译时导出 `.cache/editor-blueprint.json` 给编辑器用——**改了蓝图后要先 `npm run assets:world`**。
- 斜路是 `shapes` 里的 `stroke`（`flat` = 两端切平，`mark` = 车道线）；围栏是 `fences`（`pts`/`wall`/`piers`/`force`）；它们和运动场、蓝图修改都会随部署后的 bake 并入 `baked.json`（`hide`/`edit` 按层顺序叠加）。
- 限制：球门/篮架只有一种朝向的精灵；围栏遇斜线是阶梯状；运动场的**碰撞块**（蓝图 `blocks`）不会跟着改——围栏、球门、篮架本身有碰撞，运动场地面上的整块碰撞（例如西区运动场、体育中心）要改的话跟我说。

## 室内编辑器（2026-11-03）
地图编辑器顶栏的「室内编辑器 →」，或直接打开 `http://127.0.0.1:5174/interior`。编辑的是 `data/interiors/<id>.json`（每间室内一个文件，**直接保存进这个文件**，不走手动层/bake；改前自动备份在 `.cache/interior-backups/`，git 里也有历史）。
- **选一间室内**（顶栏下拉），可「新建」「复制」；右侧改**名称、提示语、主题**（办公室/教室/图书馆/食堂）、**房间大小**、**门洞**（南墙，进出口）、**西墙玻璃隔断**、**开放入口**。
- **旋转**：选中后按 `R`（Shift+R 反向）或点「旋转」：**椅子**在四个朝向的专用图之间切换，**其他家具顺时针转 90°**（占地的宽高跟着互换，长桌可以竖放）；摆放时按 `R` 转手里的那件；墙面挂件（空调、字画、横幅…）不能转。
- **方向键 / 小键盘**：选中东西后按方向键（或小键盘 4/6/8/2）一格一格微调位置；没选中时平移画面。点一下画布就能让输入框失焦，方向键不会再被它们吃掉。
- **家具互动**：家具面板的「互动」框填一句话，玩家走近按 E 会弹出（214 室横幅就是迎新群号）；有互动的家具在编辑器里标黄色 E。
- **横幅 / 字画 / 白板上的字**：选中后右侧「文字」框直接改（横幅横排、字画竖排，字号随字数自动缩小，最多 16 字），画面里即时可见。
- **摆家具**：左侧按分类选一件（桌椅 / 柜子电器 / 小件 / 墙面挂件 / 图书馆 / 食堂），「摆放」工具点格子放下（红框 = 压到墙或别的家具）；「选择」工具点选、拖动、拖空地**框选**多个（Shift+点击增减）、方向键微调、`R` 换椅子朝向、`Ctrl+D` 复制、`Delete` 删除、`G` 显示占地。**桌上的小件**（水瓶、书堆、电脑、保温壶）自动摆在桌面上（不占地、盖在桌子上），也可以给任何东西勾「摆在桌面上」。墙面挂件（空调、字画、横幅、白板、挂袋）摆在北墙上，不占地。
- **玻璃隔断**：「+ 玻璃隔断」加一道竖向隔断（一格厚，指定所在列、起止行），可留**内部门洞**（起行、高 2~4 格）；隔断挡路，只有门洞能过。214 室就是用它分成外间和里间。
- **NPC**：「+ NPC」，改名字、外观、朝向、位置和台词（一行一句，最多 8 句）；**文字牌**（墙上的字，像素字体）；**窗户**（北墙，可挂窗帘）。
- 画面和游戏里一致：同一套家具图集、同一套前后遮挡。**保存 → 「保存并生成预览」**（几秒）会重新生成背景图（地板/墙/窗改了才需要）和图集；改了「开放入口」或建筑的「室内」设置后，再点「**生成地图（让入口生效）**」，门口才会出现"E 进入"。
- **建筑 → 室内**：地图编辑器「改建筑」面板里新增「室内」下拉：选这栋楼正门进哪间室内（只有勾了「开放入口」的才真的开放）。
- **多层大楼（2026-11-10）**：同一栋楼每层一个文件，数据里写 `floor`（层号）、`building`（同一栋楼写同一个名字）、`stairs`（楼梯口：`dir` up/down、`x`/`y`、`to` 目标室内 id）；一层要有 `exit`（南墙门洞），二层以上没有 `exit`、只能走楼梯；楼梯两头要成对（A 的 up 对着 B 的 down），`npm run assets:interiors` 会检查并报错。**编辑器里还不能画楼梯 / 改层数**，要改楼梯请直接改 JSON 或告诉我。建筑 → 室内的对应在 `data/campus/interior-links.json`（建筑 id → 一层的室内 id，一层要 `open: true`）。
- **椅子能坐**：椅子 / 沙发 / 凳子（`chair`、`chairup`、`bchair_*`、`gchair`、`stool`、`campchair`、`sofa`）自动可坐，座位由占地算出；四周被堵死的椅子不可坐，编译时会警告。
- 室内规则：北墙占上面 3 格，西/东/南各 1 格墙；南墙门洞走出去 = 回到校园（站回楼的正门口）。家具脚印 = 占地（人走不过去）。进房间时的相机会把房间居中。
- 家具素材是程序生成的（`tools/art/furniture.ts` 老的 + `tools/art/furniture-office.ts` 办公室这批，目录与中文名在 `FURN_INFO`）；要新增家具样式，告诉 Claude。
- 限制：室内目前只有自己可见（别的玩家看不到你）；非椅子家具的旋转是把正面图直接转过去，侧面不如专用图好看；NPC 是站桩，不会走动。
- 地图编辑器里：选中物件/图形/围栏/建筑后，方向键也会微调它（一次一个吸附步长，Shift = 1 格）；没选中时平移画面。

## 已知限制
- **门**：只能开在翼体的南面（引擎的限制）；每段翼体最多一扇门；新建筑的门默认在第一段南面正中。
- 校园商店、校园墙是广场里的"物件"，不是建筑，不能在这里移动（要改位置跟我说）。
- 蓝图里已有的**运动场地面/白线、围栏围墙、道路、广场铺装、绿地**可以点选去掉或原位修改（见上一节）；其余的（树列、灌木、车位、文字牌…）不行，只能擦除/涂盖。已有的物件可以删除/移动（通过擦除）。
- 小地图/大地图上的楼名、门前互动区（留言板、商店、校园墙）、文字牌不会自动跟着楼走；移动了楼要告诉我，我再校对。
- 编辑器里涂的地面是半透明草图，材质真实贴图要点「保存并生成预览」才看得到；手动摆的物件是直接用游戏里的精灵画的。
- 只管外部地面和物件；室内、文字牌、互动区、碰撞块不在编辑器里（物件的碰撞跟着物件走，和自动摆放的一样）。

## 给 Claude 的流程
1. 用户说"编辑器改好了" → `git diff data/campus/manual.json` 看改了什么（几块地面、多少物件、擦除范围），必要时 `npx tsx tools/reference/compare.ts …` 出对照图自己看一眼；
2. `npm run assets:world`（有缓存，十几秒）→ `npm test`（含 manual 校验）；
3. 同步 `docs/FEATURES.md`、在 `docs/CHANGELOG.md` 顶部加一节（写清楚改了哪一带），提交（`-F` 消息文件）、按用户指示推送；**部署只在用户说"部署"时做**；
4. 别手工改 `manual.json` 去"覆盖"用户的编辑；要调整先问。
