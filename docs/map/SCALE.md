# 尺度约定

**现行比例：1 格 = 16 px = 2.5 m**（`data/campus/geo.json` 的 `world.scale = 2`；世界 704×544 格，约 1760 m × 1360 m）。蓝图仍以原来的"5 m/格"记录，编译时 `tools/world/scale.ts` 把几何 ×2；按像素设计的东西（精灵、间距、密度、门宽、标线粗细）不放大。对照用的 5 m/格版本：`npm run assets:s1`，访问 `/?world=generated-s1`。

| 对象 | 尺寸 | 说明 |
|---|---|---|
| 世界格 | 1 格 = 16 px = **2.5 m** | 平面布局按真实校园缩放 |
| 人物 | 18×36 px 帧（身体约 1×2 格） | 星露谷"大头小身"比例，相对真实约放大 2~3 倍（游戏化取舍） |
| 阔叶树 | 冠宽 ≈ 3 格，总高 ≈ 3.5 格 | 树按米保持 |
| 建筑 | 一层 22 px 立面 + 屋顶深度 = 平面深度 | 6 层楼立面 ≈ 138 px ≈ 21 m，与现实吻合 |
| 道路 | 环路 3.2 格×2、主路 2.6–3.2、小路 1.4–1.8（原格） | 取自卫星量测 |
| 步速 | 92 px/s，奔跑 ×1.65，骑车 ×5 | 穿越全校步行约 2 分钟 |
| 校园商店 / 校园墙 | 16 格宽（≈ 40 m） | 图书馆广场两侧的大型建筑 |

**游戏化取舍**：平面布局（距离、方位、楼间关系）保持真实比例；人和树按星露谷尺寸画。这是俯视角游戏的惯例。默认缩放按窗口宽度自动选 2–5 倍整数（保持像素不糊）。

## 为什么放大 2 倍（2026-10-31 的决定，原方案文档已合并到这里）
- 原来平面是真实比例，但竖直方向楼高被夸大约 2 倍、人被夸大近 6 倍，楼看起来"又高又窄、人又大"。
- 只缩人会破坏星露谷 16×32 的辨识度；放大 3 倍显存太大（地面约 880 MB）。**S=2 恰好让楼高正确，且每栋楼多出 4 倍像素面积**，可以画窗帘、空调、花盆、屋顶设备等细节。
- 代价：地面需要**流式加载**（`src/world/Streamer.ts`：只创建镜头周围条目，地面块异步加载/释放）、建筑图集分页、摆件按视野裁剪；每个片区要补"放大专属细节层"（灯行、长椅、花坛、树池、屋顶设备、行人）；手摆的小尺度构图（校名石岛的石球墩等）要改成按周长/间距自动排布。
- 已知的遗留：视差修正在 2.5 m 格下不确定度约 ±1.4 格，学院楼可能需要逐栋标定（`par` 字段，抽查未发现问题）；放大后的摆件约 1.1 万个，靠 Streamer 同屏只活跃几百个。
