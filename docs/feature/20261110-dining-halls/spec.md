## 1. 背景与目标

**主人的要求**
1. 给第一、第二、第三餐厅做室内，借鉴 nuc-campus 的餐厅地图；每个餐厅一个入口，**每个餐厅三层**。
2. 加入传送：**层间传送（楼梯）** + **从外面直达某一层**。不做室内楼层选择面板，也不做餐厅互传。
3. HUD **整套重排（电脑 + 手机）**，排版参考 nuc-campus；**小地图仍放左下角**。
4. 室内的**椅子要允许坐下**。
5. **图书馆、第一 / 第二公共教学楼**也先各做一版**可以开放**的室内，具体场景以后再完善。
6. 窗口先照他人仓库的版式做，**特色窗口以后由主人补充**。

**现状**
- 室内引擎是**单层**的：一间室内 = `data/interiors/<id>.json`，南墙一个门洞通向校园，**没有楼梯、没有楼层**。目前只开放 42 号楼 214 室（试点）。
- `data/interiors/` 里已有三份**早年的占位草稿**：`canteen.json`（通用食堂 30×20）、`library.json`（32×24，书架 / 桌椅 / 沙发，29 件家具）、`classroom.json`（26×18，课桌 / 讲台，53 件家具）。**它们都没开放**。
- 建筑：三个食堂（第一 `canteen-1`、第二 `d2-canteen`、第三 `canteen-3`，均 3 层）、图书馆（`library`，5 层，已有 `interior: library` 但未开放）、第一公共教学楼（`public-1`，5 层，已有 `interior: classroom` 但未开放）、第二公共教学楼（`public-2`，5 层，**没有 `interior` 字段**）。
- **坐下现状**：校园里的长椅能坐（按 E）；室内**只有「我的宿舍」里摆放的家具能坐**。我们数据里写死的室内（214 室、将来的餐厅 / 图书馆 / 教室）的椅子**现在坐不了**，需要新做。
- 定点传送（Y）里已有三个餐厅、图书馆、两个教学楼，但只传到**门口**。
- 室内目前只有自己可见（别的玩家看不到你）。
- HUD 现状：左上头像 + 菜单 + 世界 + 金币；右上时钟 + 地点 + 好友 / 留言板 / 公告按钮；左下小地图；右下聊天。

**nuc-campus 能借什么、不能借什么**（许可：代码 MIT、素材 CC0，但餐厅内容是它那所学校的）
- 借**版式范式**：长方形房间，北墙一排取餐窗口、窗口上方挂招牌、窗口下是取餐台；中间几组餐桌；角落绿植和楼梯口；有学生坐着吃饭、有人排队；每个餐厅用不同墙色 / 地板区分。
- 借**多层结构**：每层窗口不同；楼梯口直接画在地板上，上 / 下成对出现。
- 借**文档纪律**：每个窗口 / 招牌有出处，核实不了的标「未核实」。
- **不借**：它的窗口名、菜品、文字、美术、代码。窗口名先用泛称（大众套餐、面食、米饭套餐、小炒……），**全部标未核实**，主人以后补特色窗口；家具、招牌自己程序化画。

**目标**
1. 三个餐厅各自能从正门进入，每个餐厅 3 层（9 间室内），层间用楼梯互通。
2. 图书馆、第一 / 第二公共教学楼各有一版可进入的室内（第一版，场景简单、以后完善）。
3. 室内的椅子 / 沙发能坐下。
4. 传送面板里每个餐厅可以直接选 1F / 2F / 3F。
5. HUD 改成角落堆叠排版（左上一列、右上一列、底部提示条；小地图留左下），电脑和手机都不互相遮挡。

**非目标（这次明确不做）**
- 其他建筑的室内（宿舍楼、实验楼、行政楼等）**仍然关闭**；民族餐厅、学生超市暂不做。
- 图书馆 / 教学楼的**精细场景**（第一版只求可进、可走、可坐、像那么回事）。
- 室内里互相看到别的玩家（沿用「室内只有自己可见」）。
- 室内「楼层选择面板」、餐厅互传、室内里按 Y 传送。
- 点餐 / 买饭 / 经济玩法；NPC 走动 / 动态客流。
- 真实窗口名、真实布局的核实（以后由主人补）。

## 2. 用户与场景

1. 玩家走到第二餐厅门口 → 「E 进入：第二学生食堂」→ 淡出，进入 **1F**，站在南墙门洞里面。
2. 看到北墙一排窗口、几组餐桌、学生和打饭阿姨；走到餐桌边，**按 E 坐在椅子上**，推方向键起身。
3. 走到楼梯口 →「E 上二楼」→ 淡出，进入 **2F**，站在楼梯口旁。
4. 回到 1F，走出南墙门洞，回到校园（站在餐厅正门前）。
5. 在校园按 Y，「食堂」组里选「第三餐厅 · 3F」→ 传到餐厅门口 → 自动进入 3F。
6. 走到图书馆 / 教学楼正门按 E，进入一层大厅 / 教室，同样能走动、能坐。

## 4. 规则与数值

- 房间大小：餐厅每层 32×22 格上下；图书馆 / 教学楼第一版沿用草稿尺寸（32×24 / 26×18）略调；上限遵守校验（宽 8~48、高 8~40）。
- 站桩 NPC 每层 ≤ 6 个（校验限制 ≤ 12）；家具每层 ≤ 200 件（校验限制 ≤ 500）。
- 座位：坐下的触达距离沿用 `SIT_REACH`（26 像素）；室内座位不上报服务器（室内只有自己可见）。
- 传送冷却不变（8 秒）。**不引入新的经济或奖励**，没有「刷」的漏洞；新状态只有「当前楼层」和「是否坐着」，只在客户端场景里，不落盘。
- 楼层互通是纯本地操作，不需要冷却。

## 6. 数据与协议（概要，细节在 plan）

- **建筑**：三个餐厅、`public-2` 在蓝图里加 `"interior"`；`canteen-N-f1`、`library`、`classroom`、`classroom-2`（暂定 id）加 `"open": true`。
- **传送**：优先方案是**不改协议**：传送消息仍用现有 id（`canteen-1/2/3`），「进哪一层」只记在客户端，服务器把人传到门口、回包后客户端自动进入对应楼层。只改 `src/shared/teleport.ts`（加楼层列表）和客户端面板。**不新增消息类型、不改存档字段。**
  - 改了 `src/shared/*`，按约定服务端要同步测试 / 合并 / 部署；本方案服务端**代码不变**，但共享文件变了，plan 里会写明部署顺序。
- **老存档**：不受影响。

## 7. 安全、隐私与内容

- 室内数据是静态文件，没有玩家输入；NPC 台词是我们自己写的，**不含真实人名、电话、微信群号**。
- 传送仍由服务器校验（位置、冷却、状态），客户端只负责「到了之后进哪层」，不替服务器做决定。
- 窗口 / 招牌若参考真实餐厅，要么核实后写来源，要么标「未核实」（R10）。
- 版权：只借 nuc-campus 的**版式思路**，不复制它的代码、美术和文案（它的 MIT / CC0 许可允许，但我们的美术仍全部自产，避免来源混杂）。

## 8. 性能与成本

- 室内底图按需加载：**只在进入对应楼层时下载**，首屏不增加；9 + 3 张底图（WebP 无损）每张预期数十 KB。
- 家具图集：新家具并进现有室内图集；plan 里量实测增量。
- HUD 重排是纯 DOM / CSS，无运行时性能影响。
- 无服务器 CPU / 内存 / 磁盘影响。
