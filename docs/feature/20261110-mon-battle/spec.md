# IR #5 · 精灵对战第一批完善（B 方案）

> 对应 Issue：[EXIST-D/PixelCampus#5](https://github.com/EXIST-D/PixelCampus/issues/5)
> 规范：[docs/feature/spec.md](../spec.md)（模板）
> 状态：已确认并开工（2026-11-10）；测试服已部署（2026-11-10 16:32），正式服待部署

## 0. 已确认的设计（本轮问答）

| 项 | 结论 |
|---|---|
| 方案 | **B**：按等级技能表推导可学列表；不做历史、不做 `pend`、不补发 |
| 可学范围 | 当前阶段 + 已经过的前序阶段；`lv <= 当前等级`；排除当前已带；**不含未来阶段** |
| 列表来源 | 服务端下发 `mon_data.learnable?: Record<string, string[]>`，按等级排序，不持久化 |
| 客户端职责 | 只显示；不做本地回退；不做乐观更新 |
| 替换时机 | 只在战斗外（精灵面板）；战斗中不能换 |
| 成本 | 免费、不限次数 |
| 界面 | 当前技能每条右侧「更换」；有空槽时「学习新技能」；从当前技能出发 |
| 协议 | `mon_replace { id, move, drop }`；`drop = -1` 放空槽，`drop >= 0` 替换该下标；`PROTOCOL_VERSION` 不升 |
| 服务端校验 | 精灵存在、技能在 `learnable`、当前没带、`drop` 合法、不在战斗中 |
| 成功回包 | `mon_result { ok, msg }` + 推回 `mon_data` |
| 提示文案 | 升级满技能：「想学会 X，但技能已满；可在精灵面板更换」；进化也发 `learn{full:true}` |
| 服务端 | 先做客户端 + 共享规则；服务端代码权限 / 实现 / 上线时间：**待定**（见 §5） |

## 1. 问题：用户到底卡在哪

1. **技能满了以后没有出路。** 精灵有 4 个技能槽，升级 / 进化想学新技能时只提示「技能已满」，之后永久丢失；精灵面板里没有查看、更换或找回技能的入口，玩家不知道该怎么办。
2. **选招靠猜。** 战斗出招菜单只有技能名和 PP，没有属性、威力、命中，也不提示对当前对手的克制；对手只有血条没有 HP 数值。
3. **打完不知道发生了什么。** 战斗结束只有滚动日志，没有结算汇总；收服后不知道精灵进了队伍还是背包。
4. **刷级太拖。** 战斗事件每个 380–700ms，没有快进。

## 2. 验收标准

### 2.1 应该发生（正向）

**技能替换**

- **A1.** 当 `mon_data.learnable[m.id]` 非空且 `m.mv.length === moveSlots(sp)` 时，精灵详情里每条当前技能右侧显示「更换」；点「更换」后显示可学列表；选择一项并指定槽位后，客户端发出 `mon_replace { id, move, drop }`，`drop` 等于该槽位下标。
- **A2.** 当 `m.mv.length < moveSlots(sp)` 且 `learnable` 非空时，详情里显示「学习新技能」；点击后客户端发出 `mon_replace { id, move, drop: -1 }`。
- **A3.** 服务器成功时，客户端收到的 `mon_data` 满足：`m.mv[drop].id === move`、`m.mv[drop].pp === CONTENT.moves.get(move).pp`（新学满 PP）；旧技能不再出现在 `m.mv` 里；`learnable` 不再包含 `move`。
- **A4.** `drop = -1` 成功时，`m.mv.length` 增加 1，原有技能顺序和内容不变。
- **A5.** 可学列表包含：当前物种 + 已经过的前序阶段的 `learnset` 中 `lv <= m.lv` 的技能；不包含未来阶段、不包含当前 `mv` 里已有的技能。例：猫系 `chain = [c00a, c00b, c00c]`，当前是 `c00b`，只并 `c00a` + `c00b`，不并 `c00c`。
- **A6.** 页面刷新 / 重连后，服务器的 `mon_data` 仍返回替换后的 `mv` 与 `learnable`，客户端显示一致。
- **A7.** 升级时技能满：战斗日志显示「想学会 X，但技能已满；可在精灵面板更换」；`m.mv` 不增加该技能。
- **A8.** 进化时技能满：战斗事件流里出现 `learn { full: true }`；日志显示同 A7；`m.mv` 不增加该技能。
- **A9.** `mon_data.learnable` 缺失（旧服务端 / 离线）时，精灵面板不显示「更换」「学习新技能」入口；页面不报错。

**战斗信息**

- **A10.** 出招菜单每个技能显示：属性文字、物理 / 特殊、威力、命中、当前 PP / 最大 PP；对当前对手的倍率与 `typeMult(CONTENT.elements, move.type, foe.types)` 完全一致。
- **A11.** 倍率为 0 显示「无效」；倍率 ≥ 2 显示「效果拔群 ×N」；倍率 < 1 且 > 0 显示「效果不佳 ×N」；倍率 1 不显示倍率文字。
- **A12.** 对手卡片显示 `hp/max` 数值；我方卡片显示属性徽章。

**结算页**

- **A13.** `phase === 'over'` 时，菜单区显示结算摘要：结果 + 本回合 `ev` 里的经验、升级、进化、学招、收服；没有对应事件就不显示对应行。
- **A14.** `ev` 为空（重连后直接 `over`）时，只显示结果，不显示空行、不报错。

**快进**

- **A15.** 点击快进按钮后，按钮 `aria-pressed` 变化；后续动画 / 文字等待时长约为原来的 35%，且不低于 80ms。
- **A16.** 刷新页面后快进状态保留（`localStorage` key 固定）。
- **A17.** `localStorage` 读写抛异常时，快进默认关闭，页面不报错。

### 2.2 绝对不能发生（反向）

- **N1.** 客户端在未收到服务器 `mon_data` 前，**绝不能**本地修改 `m.mv`（不能乐观替换 / 删除 / 追加）。
- **N2.** `mon_data.learnable` 缺失时，客户端**绝不能**自己用 `learnsetOf` 本地推导并显示列表（本批定为纯服务端下发）。
- **N3.** 客户端**绝不能**把 `learnable` 里未知的 move id 当成合法技能显示；查不到就跳过，不崩溃。
- **N4.** 服务器**绝不能**接受不在 `learnable` 里的技能。
- **N5.** 服务器**绝不能**接受当前 `mv` 里已经有的技能。
- **N6.** 服务器**绝不能**接受越界的 `drop`（满槽时 `drop = -1`，或 `drop >= mv.length`）。
- **N7.** 服务器**绝不能**在战斗进行中处理 `mon_replace`。
- **N8.** 服务器**绝不能**因为替换让 `m.mv.length` 超过 `moveSlots(sp)`。
- **N9.** 替换 / 学习**绝不能**产生重复技能 id。
- **N10.** 旧存档（没有 `pend` 字段）**绝不能**导致读取失败、崩溃或技能丢失。
- **N11.** 战斗中打开精灵面板**绝不能**成功（现有 `anyOverlay` / `battleUi.isOpen` 约束不能被绕过）。
- **N12.** 快进**绝不能**改变回合顺序、伤害结果、服务器计时或事件顺序。
- **N13.** 战斗信息里的倍率**绝不能**与引擎 `typeMult` 不一致。
- **N14.** `foe.max = 0` 或缺失时，界面**绝不能**出现 `NaN` / `Infinity` 血条。
- **N15.** 结算页**绝不能**重复显示同一次经验 / 升级 / 进化 / 学招事件。
- **N16.** 玩家写的文字**绝不能**用 `innerHTML` 渲染（沿用现有约定，全部 `textContent`）。

## 3. 失败时怎么办

| 失败 | 客户端行为 | 数据 |
|---|---|---|
| `mon_replace` 被服务器拒绝（`ok: false`） | 显示 `mon_result.msg`；不本地修改；按钮恢复可用 | 不变 |
| `mon_replace` 超时 / 无响应 | 超时后恢复按钮可用；提示「服务器没有响应，请稍后再试」；不本地修改 | 不变 |
| `mon_data` 没有 `learnable` | 不显示替换入口；不本地推导；不报错 | 不变 |
| `learnable` 里全是客户端不认识的 move id | 隐藏可学列表；不崩溃 | 不变 |
| `learnable` 里混入当前已带的技能 | 客户端过滤掉；不显示重复项 | 不变 |
| `drop` 越界 / 精灵不存在 / 技能不合法 | 服务器拒绝；客户端显示错误；不本地修改 | 不变 |
| 战斗中收到替换请求 | 服务器拒绝；客户端本来就不能打开面板 | 不变 |
| 连续点击 / 重复请求 | 第一次请求后按钮禁用；服务器按当前状态校验，重复请求不会产生第二次替换 | 不变 |
| 断线 | 面板保持当前显示；不本地修改；重连后 `monGet` 刷新 | 不变 |
| `localStorage` 异常 | 快进默认关闭；不报错 | 不变 |
| 结算 `ev` 为空 | 只显示结果；不显示空行 | 不变 |
| 对手 `max` 为 0 / 缺失 | 血条按 `max(1)` 显示；不出现 NaN | 不变 |

## 4. 这次不做什么

- 不做 `Mon.pend` 待学队列；不做历史记录；不补发老玩家以前错过的技能。
- 不做技能回忆 NPC、不做技能学习器 / 招式机器、不做活动技能。
- 不做免费之外的收费 / 冷却 / 每日限次。
- 不允许战斗中换技能。
- 不把未来进化阶段的技能提前解锁。
- 不在客户端本地推导可学列表（纯服务端下发）。
- 不做收服去向字段（结算页只显示「收服了 X」，不显示具体进了队伍还是背包）。
- 不做状态异常、能力等级、非伤害招式（#6）。
- 不做战斗道具、携带道具 / 树果、捕捉道具分层（#7）。
- 不做精灵图鉴页（#8）、训练家 NPC（#9）、对战奖励 / 成就 / 任务（#10）、猫战 AI / PvP（#11）。
- 不改服务端代码；服务端部分待定（见 §5）。
