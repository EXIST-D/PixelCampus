## 1. 背景与目标
- **问题**：现在改完代码要么只在本机验证（单人、`localhost`、没有真实 HTTPS / 手机 / 多人网络环境），要么直接部署到正式服（有真实玩家，出问题会影响他们）。想要**一个和正式环境同构的测试环境**，可以随时部署最新代码、多人 / 手机联测，边运行边改。
- **目标**：
  1. 一条命令把当前代码部署到测试环境（和正式部署同一套构建，只是目标不同）。
  2. 测试环境与正式环境**数据完全隔离**（独立数据目录、独立管理员口令、独立端口 / 域名），不会碰到真实玩家档案。
  3. 能多人 / 手机联测（可以用机器人模拟在线玩家），并方便重置数据、回滚。
  4. 不影响正式环境和同机其他服务（资源上限、访问控制）。
- **非目标**：不做自动化 CI/CD（仍由主人手动触发）；不做流量切换 / 灰度；测试环境不对公众开放。

## 2. 用户与场景
- **主人 / 受信任的协作者**：开发完一个功能后 `npm run deploy:test` → 打开测试地址，用电脑 + 手机联测 → 没问题再部署正式环境。
- 协作者（服务端权限者）合并前可以在测试环境验证他们的分支。

## 3. 功能需求
| 编号 | 需求 | 优先级 |
|---|---|---|
| R1 | 有一个独立的测试环境（独立进程 / 数据目录 / 端口 / 访问地址） | P0 |
| R2 | `npm run deploy:test` 一条命令部署当前代码到测试环境，默认不会部署到正式环境（反之亦然，目标要显式） | P0 |
| R3 | 测试环境的管理员口令、玩家档案与正式环境互不相通；默认从空数据开始 | P0 |
| R4 | 访问受限：不对公众开放（**隐藏路径**：路径含随机串，不公开，`noindex`） | P0 |
| R5 | 一键重置测试数据；可选：用脱敏样本数据初始化 | P1 |
| R6 | 能用 `npm run bots` 模拟多个在线玩家 | P1 |
| R7 | 页面上有「测试环境」醒目标识，避免和正式环境混淆 | P1 |
| R8 | 构建产物的路径前缀可配置（正式 `/pixel/`，测试环境自己的前缀或根路径） | P0 |

## 4. 规则与数值
- 测试进程内存上限 ≤ 200MB；最大同时在线 ≤ 30；不与正式环境共用数据目录。
- 测试数据**不使用真实玩家档案**（含昵称 / 学号等个人信息）；需要真实形态的数据时用脱敏样本。

## 5. 界面与交互
- 命令行：`npm run deploy:test`（构建 → 同步 → 重启 → 打印 healthz）；`npm run deploy`（正式）保持不变并增加目标确认。
- 测试页面左上角 / 标题栏显示「测试环境」标记。

## 6. 数据与协议
- 无协议和存档字段变化；新增部署配置（目标主机、应用目录、服务名、端口、路径前缀）和测试环境的数据目录。

## 7. 安全、隐私与内容
- 访问控制（R4）；测试环境口令与正式不同，且不经过聊天；不把真实玩家数据拷到测试环境；测试环境不接公共域名主页链接。

## 8. 性能与成本
- 额外内存约 100~150MB（空数据）；磁盘几百 MB；不增加正式环境负担（若与正式同机，需限制资源并避开高峰构建 / 上传）。

## 9. 验收标准
- [ ] A1：`npm run deploy:test` 后能在测试地址打开游戏、联机、多人互相看见。
- [ ] A2：测试环境登录 / 发言 / 买东西等不影响正式环境的任何数据（对比正式 `players.json` 无变化）。
- [ ] A3：未授权访问测试地址被拒。
- [ ] A4：`npm run deploy` 仍只部署正式环境，不会误发测试；两者的目标在命令输出里明确显示。
- [ ] A5：重置命令能把测试数据恢复为空 / 样本。

## 10. 已拍板的问题（2026-11-10，主人）
- **放在哪**：正式服务器上再起一个独立实例（同一个域名和 HTTPS，手机联测最像线上）。
- **访问控制**：隐藏路径（路径里带随机串，不对外公布、不放进任何公开页面或文档；搜索引擎 `noindex`）。
- **HTTPS**：用正式域名已有的证书。

## 11. 后续（第二阶段，待启动）
- 协作者在测试环境改服务端并联测，主人确认后再上正式：见 [服务端协作指南](../../process/SERVER_COLLABORATION.md) 的「测试环境」一节。
