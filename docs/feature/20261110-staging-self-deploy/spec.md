## 1. 背景与目标
- **问题**：测试环境已经有了，但现在只有主人能部署（`npm run deploy:test`）。协作者改了服务端后，要么等主人代劳，要么没法联测。
- **目标**：
  1. 受信任的协作者能**自己**把分支部署到测试环境、看日志、重置数据；
  2. 协作者**拿不到服务器登录权限**，也碰不到正式环境、nginx、玩家数据、其他服务；
  3. 每个协作者的权限可单独撤销；
  4. 正式环境部署权仍只在主人（[ADR 0008](../../adr/0008-deploy-by-owner.md)）。
- **非目标**：不给协作者正式环境的任何权限；不做对公众开放的自助部署；本阶段不做自动审批流（正式环境上线仍由主人手动）。

## 2. 用户与场景
- **受信任的服务端协作者**：改完分支 → `npm run deploy:test` → 打开测试地址联测 → 看日志排错 → 需要时重置测试数据 → 提 PR → 主人确认后合并并上线。
- **主人**：给协作者开通 / 撤销权限；随时看到谁在什么时候部署过。

## 3. 功能需求
| 编号 | 需求 | 优先级 |
|---|---|---|
| R1 | 协作者用**自己的 SSH 密钥**连到一个受限账号，只能执行白名单命令：`deploy`（上传并部署）、`status`、`logs`、`reset`（清空测试数据）、`rollback`（回到上一个版本）、`set-admin-hash`（只收哈希） | P0 |
| R2 | 受限账号不能获得 shell、不能转发端口、不能执行其他命令；只能写测试应用目录，只能重启测试服务 | P0 |
| R3 | 一次只允许一个部署（加锁），并保留最近 N 个版本供回滚 | P0 |
| R4 | 记录每次操作（时间、哪把密钥、做了什么）；主人可查看 | P1 |
| R5 | 测试服务被进一步沙箱化：看不到正式环境数据、nginx 配置和其他服务的文件，**不能访问外网** | P0 |
| R6 | `npm run deploy:test` 支持「受限模式」（协作者的机器上用 tar + ssh 流式上传，不需要 root） | P0 |
| R7 | 撤销：主人删除某个公钥即可立即失效；隐藏路径可轮换 | P0 |
| R8 | （以后）GitHub Actions：推送 `staging/*` 分支自动部署，使用受限密钥；正式环境用需要主人批准的 `production` 环境 | P2 |

## 4. 规则与数值
- 上传包上限 200MB；部署超时 120 秒；同时 1 个部署；保留最近 3 个版本。
- 协作者人数与密钥：每人一把独立密钥。

## 5. 界面与交互
- 命令行：`npm run deploy:test`（协作者机器上自动走受限模式）；`npm run test-env -- logs | status | reset | rollback`。

## 6. 数据与协议
- 无协议和存档字段变化；服务器上新增：受限部署账号、两个受 root 管理的脚本、一条 sudo 规则、版本目录。

## 7. 安全、隐私与内容
- 威胁模型：**受信任的协作者**（不是公众）。能部署 = 能在测试沙箱里运行任意服务端代码，所以必须靠沙箱（R5）和权限边界（R2）兜底，而不是只靠信任。
- 测试环境默认空数据，不放真实玩家信息；协作者不需要、也不会拿到敏感词库的原文（词库留在服务器上，部署包不含）。
- 隐藏路径是访问口令，只告诉协作者；人员变动时轮换。

## 8. 性能与成本
- 额外占用可忽略（一个受限账号 + 版本目录，每个版本约 5~10MB）。

## 9. 验收标准
- [ ] A1：协作者密钥能 `deploy` / `status` / `logs` / `reset` / `rollback`，其他命令一律被拒；
- [ ] A2：用该密钥无法获得 shell、无法读写测试目录之外的文件、无法重启其他服务；
- [ ] A3：从测试进程里读不到正式数据目录、nginx 配置、其他服务的文件；测试进程不能连外网（出站被拒）；
- [ ] A4：两个人同时部署，第二个被拒并提示；
- [ ] A5：撤销公钥后立刻不能再连接；
- [ ] A6：操作日志里能看到谁什么时候做了什么；
- [ ] A7：正式环境全程不受影响（`healthz` 档案数 / 进程不变）。

## 10. 未决问题
- [ ] 要不要先把 `server/` 整理成独立的私有仓库（协作者需要拿到服务端代码）？建议先做。
- [ ] 协作者的第一位是谁、有几个人？（决定是否需要 R8 的自动化）
- [ ] 日志是否允许协作者看（可能含玩家昵称等测试数据；测试环境默认只有测试账号，一般可以）。
