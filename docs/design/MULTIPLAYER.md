# 多人联机：需求、决策与各批功能设计

> **定位（2026-11-10）**：这是「按批次记录的设计历史」，不是协议手册。**当前有哪些消息**看自动生成的 [PROTOCOL.md](../architecture/PROTOCOL.md)（以 `src/shared/protocol.ts` 为准）；现有功能看 [FEATURES.md](../FEATURES.md)；每次更新看 [CHANGELOG.md](../CHANGELOG.md)。下文个别细节（限频数字、字段）可能已被后续批次改动，以代码为准。

> 本文按时间记录联机相关的设计（协议、移动校验、社交、玩法）。**货币/商店/校园墙见 [ECONOMY.md](ECONOMY.md)；人物/小猫 Rig 与外观自定义见 ART_CHARACTER_CAT_DESIGN.md；各批功能的最新状态以 [FEATURES.md](../FEATURES.md) 为准。**

## 已确认的需求（用户 2026-10-31）
- 进入游戏先**创建角色**：选男/女 + **固定几个造型**（暂不做发型/肤色自选）。
- **学生证**：姓名、学院、专业（另有年级、签名、虚拟证号）。**全部用户随意填，不要求真实**；姓名对所有人可见。
- 头顶显示**昵称**；左上角**个人信息**（头像 + 昵称 + 学院专业，点击/按 C 看学生证，可修改资料）。
- **公屏**：公共聊天频道，所有在线玩家可见。
- **登录方式**：昵称 + 浏览器记住你（`localStorage`），不做账号密码。

## 第 1 阶段（已完成）：单机壳 + 联机接口

| 公屏消息格式与清洗（共用） | `src/shared/chat.ts` |
| 浏览器存档 | `src/core/profileStore.ts`（存储不可用时退回内存） |
| 新生报到 / 修改资料 | `src/ui/CreateCharacter.ts` |
| 学生证卡面（颜色由学院名哈希决定） | `src/ui/StudentCard.ts` |
| 左上角个人信息 + 学生证弹窗 | `src/ui/ProfilePanel.ts` |
| 公屏界面（Enter 聊天，Esc 退出，发送限频 0.8 秒） | `src/ui/ChatPanel.ts` |
| 公屏通道接口 `ChatTransport` + 离线实现 `LocalChat` | `src/net/chat.ts` |
| 头顶昵称牌、说话气泡 | `src/entities/Player.ts` 的 `setNameTag` / `say` |

要点：
- **可选造型**：男 `[0,2,4,6,10,11]`、女 `[1,3,5,7,8,9]`（`LOOK_CHOICES`，对应 `tools/art/characters.ts` 的 `LOOKS`）。校验保证造型必须属于所选性别，存档被改成非法造型会被拒绝。
- **安全**：所有玩家文本只用 `textContent` 渲染；清洗掉控制字符、零宽字符、双向覆盖（防伪造昵称）；按"字"截断（姓名 8、学院 12、专业 14、签名 24、聊天 80）。
- **键盘**：在输入框打字时 `main.ts` 关闭 Phaser 键盘，避免 WASD/空格被游戏截获。
- 当前公屏是**离线**的（消息只有自己看得到，界面右上角会标明）。

## 第 2 阶段（已完成）：联机服务器
**架构**：一个 Node 进程（`ws`）同时做 HTTP 和 WebSocket（`/ws`）；这部分代码在主人的私有部分，不在本仓库。开发时 Vite 把 `/ws` 代理到本机的联机服务器（协作者没有它，用 `?offline`）。

| 文件 | 作用 |
|---|---|
| `src/shared/protocol.ts` | 协议：二进制位置上报（6 字节）/ 快照（每人 7 字节，1/4 像素定点）+ JSON 控制消息 |
| `server/game.ts` | 核心：加入、移动校验、视野、公屏、限频禁言、顶号、资料更新 |
| `server/store.ts` | 玩家档案（token 哈希 → 档案与最后位置），JSON 文件，防抖 + 原子写 |
| `src/net/client.ts` | 浏览器端：连接、指数退避自动重连、公屏通道（离线只回显给自己） |
| `src/entities/RemotePlayer.ts` | 他人：昵称牌 + 落后 130 ms 的快照插值 |

**移动**：客户端自己算移动（手感零延迟），定期向服务器上报位置；服务器负责校验并在必要时拉回。具体的校验规则、阈值和限频参数属于运维细节，不写在公开文档里。

**视野**：每个客户端只收到 1000 px 内的玩家（离开半径 1200，防边界抖动）。进入/离开发 `spawn`/`despawn`（带公开资料），位置用二进制快照，且只发变化的人。当前是 O(N²) 距离判断，几百人以内没压力；上千人再换空间网格。

**身份**：浏览器随机 token 存 `localStorage`，服务器只存哈希。同一个 token 再登录会把旧连接踢下线；断线重连后回到上次位置（7 天内且仍可走）。昵称允许重名（服务器内部用编号区分）。

**公屏**：全服广播；服务器会再清洗一遍文本并限频，违规会被禁言。

**运行**：联机服务器不在本仓库里，由主人在自己的电脑上运行和维护。协作者用 `npm run dev` 并在网址后加 `?offline` 做单机开发；改了协议或共享规则，在 PR 说明里写清楚，服务端那一半由主人实现。

### 已知限制
- 没有账号体系：token 丢了（清浏览器数据）就是新玩家；昵称不唯一，可能有人冒充同名。
- 没有敏感词过滤、没有管理员命令（踢人/禁言/公告）——第 3 阶段。
- 他人只显示昵称牌，点击看学生证还没做。
- 室内（暂停）里不同步位置。NPC 仍只在本地，每个人看到的路人不同。
- 服务器没有测公网/高延迟下的体验；插值缓冲固定 130 ms。

## 公告栏（已完成）
- **玩家端**：进游戏时如果有"最新一条你还没选过不再提醒"的公告就自动弹出；「不再提醒这条」记在本机（`localStorage`），管理员发布新公告后会再次弹出；「知道了」只是关掉，下次进来还会弹。随时点侧边「公告 (N)」/ 手机菜单重新打开，下面有往期公告。管理员刚发布新公告时，正在玩的人不会被打断，只在顶部横幅 + 公屏 + 按钮角标提示。
- **管理员**：登录后公告面板顶部出现「发布新公告」，每条公告有「修改」「删除」。发布 = 新增一条（所有人再次提醒）；修改 = 原地改（不再弹窗）。标题 40 字、正文 1500 字，正文可以多行（适合写更新日志）。
- **存储**：服务器上的 `notices.json`（最多留 30 条，整份原子写）。公告内容一律 `textContent` + `white-space: pre-wrap` 渲染。

## 好友 / 私聊 / 聊天记录（已完成）
- **校园号**：服务器给每个身份分配的稳定编号（10001 起，永不变、不复用），是好友和私聊里唯一可信的身份——客户端自己填的任何东西（昵称、证号）都不可信，可以重名/伪造。显示在学生证、好友面板里；可复制发给同学。
- **加好友**：点场景里别人的角色、点公屏里别人的名字、或在好友面板「添加」里输入校园号 → 资料卡 → 发申请。对方在线会收到提示，离线的上线后在「申请」里看到。对方也申请过自己时直接成为好友。好友上限 100，待处理申请上限 50。
- **私聊**：只能给好友发，每人每分钟最多 20 条，每条最多 300 字。对方离线时存下来，上线后是未读（好友按钮/手机 ☰ 上有红色角标，公屏里提示一行）。
- **屏蔽**：会同时解除好友；被屏蔽的人不能再申请、不能发私聊。可以在「屏蔽」页解除。
- **聊天记录保存**：私聊记录追加写进 `dm.jsonl`，永久保存在服务器上，换设备/清缓存后（只要身份不丢）也能看到；打开会话时加载最近 50 条，可「加载更早的记录」；会话里有「导出」把已加载的记录保存为文本文件。公屏记录追加写进 `chat.jsonl`，新进来的玩家一进来就能看到最近 100 条（淡色显示）。
- **隐私**：私聊界面里明示"聊天记录保存在服务器上，服务器管理员可以查看"。每个会话只会发给会话双方；服务器不信任客户端，所有校验（是不是好友、有没有被屏蔽、限频、长度）都在服务端。
- **数据文件**（都在服务器的数据目录里）：`friends.json`（好友/申请/屏蔽/已读位置）、`dm.jsonl`、`chat.jsonl`、`notices.json`、`board.jsonl`、`players.json`（玩家档案：平时把变了的档案追加到增量日志 `players.json.log`，定期 / 关服时合并成完整快照）。
- **身份丢失就丢好友**：身份 = 浏览器里的随机 token（没有账号体系）；清浏览器数据/换设备会变成新身份（新校园号），旧的好友关系找不回来。后续可以做"身份备份码"。

## 背包 / 身份备份码 / 校园小猫 / 共享单车（已完成，2026-11-01）
**背包**（`src/shared/items.ts`、`server/progress.ts`、`src/ui/BackpackPanel.ts`）：物品存在服务器的玩家档案里（`players.json` 的 `inv`：物品 id → 数量），跟着身份走。客户端只读——所有增减由服务器按规则执行并推整份背包（`inv`，可带 `gain` 提示"获得了什么"）。新增物品：在 `ITEMS` 加一项 + 在 `tools/art/items.ts` 画同名图标 + `npm run assets:art`。将来"背包里有 X 才能触发彩蛋/互动"：服务器 `progress.take/grant` 判断，不信任客户端。每天（北京时间）第一次进入补猫粮到 5 包。

**身份备份码**（`src/shared/backup.ts`、`src/ui/BackupPanel.ts`、`src/net/restore.ts`）：身份 = 浏览器里的 token（服务器只存哈希）；备份码 = token 的可读形式（`PX-` + Crockford Base32，带 16 位校验，容忍大小写/空格/横线/O0/IL1）。恢复流程：`restore` 消息（hello 之前，不建立会话）→ 服务器认识这个 token 就回 `restored` + 学生证资料 → 客户端存 token 和资料再重载页面。同一 IP 10 分钟最多尝试 10 次。备份码 = 身份钥匙（拿到就能用这个身份），界面已加警告。入口：学生证「身份备份」、新生报到界面「已有备份码？恢复身份」。

**校园小猫**（`src/shared/cats.ts`、`src/entities/Cat.ts`、`src/ui/CatPanel.ts`）：共 32 只——28 只家（位置/毛色/名字）由固定种子从行人出生点挑，另有 4 只写死在图书馆正门前（书虫/墨水/书签/馆长，编号 28–31，接在随机猫后面，不影响老玩家的好感度编号）——服务器和所有客户端算出来一致，大家看到同一只猫在同一个地方；游走只在本机，不同步。好感度存在玩家档案（`cats`），档位：陌生/眼熟/熟悉/亲密（0/4/12/30）。摸一摸 +1（每猫 6 秒冷却）、喂猫粮 +3 / 猫条 +8（每猫 20 秒冷却，消耗物品）；熟悉之后投喂可能回赠银杏叶；升到"熟悉"得猫条，升到"亲密"得猫条 ×2 和爱猫徽章。服务器按猫的"家"校验玩家距离（`CAT_SERVER_REACH`）。不熟的猫（好感 < 4）见到奔跑/骑车的人会躲。离线单人模式只有摸猫动画，不记好感也不能喂。

**共享单车**（`src/core/const.ts` 的 `BIKE_MULT`、`src/entities/Player.ts`、`tools/art/bikes.ts`）：停车架（`bikeRack`）旁按车架坐标确定地停几辆黄色小车，另外南门**门内**东西向小路两边的草坪上（各一条黄色停放块）整齐停了 20 辆（`src/shared/bikes.ts` 的 `gateBikes()`，每侧 2 排 × 5 辆，全部在校园里面，2026-11-02 起不再放墙外；服务器同样用它判断上车位置）；走到旁边按 E 扫码骑行，骑行中 E 锁车下车（车不会少，随时可用）。**骑行速度 = 步行 × `BIKE_MULT`（现为 5，≈460 px/s，穿过全校约 25 秒；最初是 10 倍，玩家反馈过快）**，想调快慢只改这个常数。协调性处理：起步 0.7 秒加速、松手 0.3 秒刹停、急转掉速、蹭墙减速；碰撞每帧按 4 px 分步（高速也不穿墙）；镜头跟得更紧并沿行进方向预读地面块；骑行时每秒上报 30 次位置（平时 15）。服务器：`ride` 消息，上车必须在停车架 90 px 内；骑行中速度/额度按单车速度算，下车立刻收回；flags 的 bit4 是骑行标志，**由服务器判定**，客户端自称无效；其他玩家按此画出"上半身 + 两层单车"。不画任何品牌标志（只借"黄色共享单车"的通用造型）。

## 成就（已完成，2026-11-01）
`src/shared/achievements.ts`（目录/校验）、`server/progress.ts`（`unlock`）、`src/ui/AchievementPanel.ts`。解锁记录存在玩家档案的 `ach`（成就 id → 解锁时间），跟着身份走（备份码恢复后还在）。客户端只读；`ach` 消息推整份记录，刚解锁的带 `new`，客户端据此弹「🏆 成就达成」。入口：电脑 `J` / 右侧「成就」（有新成就时带角标），手机 ☰ → 成就，学生证里的「🏆 成就 n/m」。
- **进入校园**：服务器在玩家每次 hello 后尝试解锁（只有第一次生效）。
- **真正的河北工程**：校名石彩蛋（E 摸三下回到原名）走完一轮时，客户端发 `ach_event: egg_done`；服务器核对玩家当前位置在校名石触发范围内（`WorldData.eggs`，来自 world.json 的 `interacts`，留 48 px 余量）才解锁。彩蛋的三步状态在客户端本地，服务器不跟踪步数——站在石头前直接发事件也能解锁，这是有意的取舍（成就没有实际收益）；以后成就带奖励时再改成服务器跟踪步数。
- **占位**：`soon_1..2` 在列表里显示为「？？？ 更多成就，敬请期待」，服务器不会解锁它们。后来加了：铲屎官（小猫「亲密」）、小憩片刻（坐下）、咔嚓！（拍照）、初次垂钓、精工湖钓手、校园跑达人、赛场飞人、勤勉学子——见下一节。新增成就：在 `ACHIEVEMENTS` 加一项（去掉 `placeholder`），再在服务器接上触发条件（需要客户端上报的，加到 `ACH_EVENTS` 并在 `ach_event` 里校验条件）。

## 称号 / 坐下·表情·拍照 / 声音 / 每日任务 / 钓鱼 / 校园跑 / 好友位置 / 管理员控制台（已完成并部署，2026-11-01）
**称号**（`src/shared/titles.ts`、`server/progress.ts` 的 `grantTitle/setTitle/syncTitles`、`src/ui/TitlePanel.ts`）：已获得的存在档案 `tt`（称号 id → 时间），佩戴的是 `ts`。多数称号由成就自动发放（成就上写 `title` 字段），第一个得到的自动佩戴。头顶昵称上方（`Character.setTitle`）、学生证抬头下方、资料卡里显示。别人看到的是服务器认定的称号（`spawn` 带 `ttl`，换戴后对附近的人重发 `spawn`）。**管理员称号**是特殊称号（不进档案），只有管理员模式开着才显示。老玩家登录时按已有成就补发称号。

**坐下**（`src/shared/seats.ts`）：长椅 → 座位（长椅正南面第一处可站的位置，所以坐着时位置仍是合法位置）；服务器 `sit` 消息校验 70 px 内有座位，flags bit5 由服务器判定；坐着时位置上报被忽略，想走先发 `sit(false)`；画面上人物抬到椅面，椅面前沿（含椅腿）单独再画一层盖住腿。**表情**（`src/shared/emotes.ts`）：9 个，服务器限频（1.2 秒）后广播给看得见这个玩家的人，动作（抖动/跳跃/转圈）只在画面上。**拍照模式**（`src/ui/PhotoMode.ts`）：P 进入，界面全藏，镜头脱离玩家自由取景，可隐藏昵称，「拍照」把 Phaser 画面加水印后保存成 PNG（只在本机生成，不上传）。

**声音**（`src/audio/*`）：全部 WebAudio 现场合成，没有任何音频文件（无版权、无加载）。背景音乐 `compose.ts` 是纯函数作曲（白天 C 大调五声音阶 / 夜晚 A 小调、更慢更稀疏，旋律音必在音阶内，可测试）；`music.ts` 往前 0.8 秒排程；音效 `sfx.ts` 按名字播放（脚步、点击、摸猫、成就、抛竿……）。第一次点击/按键才创建 AudioContext；音量存本机 localStorage，右侧「声音」调节。**音质没法在开发环境里"听"，只验证了引擎运行、排程和音符范围——部署后请你自己听一下，觉得吵/单调告诉我调。**

**每日任务**（`src/shared/quests.ts`、`server/progress.ts` 的 `questEvent`、`src/ui/QuestPanel.ts`）：每天（北京时间 0 点换日）所有人拿到同样 5 个：固定「登录签到」（鱼饵×5+猫条×1+鱼竿×1，鱼竿已有则不重复）、「在线满 10 分钟」，另外从任务池按日期固定抽 3 个。进度只由服务器自己的逻辑触发（摸猫/喂猫/骑车/坐下/表情/发言/拍照/钓鱼/校园跑/走到湖边或图书馆广场），完成后奖励自动入包。累计"做完当天全部任务"7 天 → 成就/称号「勤勉学子」。Q 键 / 右侧「任务」。

## 精灵对战第一批（2026-11-10，协议版本 11，additive）
**共享规则**：`src/shared/monbox.ts` 新增 `evolutionLine()`（当前阶段 + 已经过的前序阶段，不含未来阶段）、`learnableMoves()`（`lv <= 当前等级`、排除当前 `mv`、按等级排序）、`learnableMap()`（给 `mon_data` 用的批量表）、`learnMove()`（`drop = -1` 放空槽，`drop >= 0` 替换该下标；校验可学列表、不重复、不超过 `moveSlots`）。`src/shared/battle.ts` 的 `evolveCheck()` 在技能满时也发 `learn{full:true}`（只提示）。
**消息**：S→C `mon_data` 增加 `learnable?: Record<string, string[]>`（精灵 id → 技能 id，服务端算、不持久化）；C→S 新增 `mon_replace { id, move, drop }`；S→C 复用 `mon_result { ok, msg }` 并推回 `mon_data`。`PROTOCOL_VERSION` 不升。
**校验**：服务器确认精灵存在、技能在 `learnable` 里、当前没带、`drop` 合法（`-1` 仅空槽；`>= 0` 下标存在）、不在战斗中；成功后更新 `mv`（新技能满 PP）并推回 `mon_data`。不需要新增存档字段。
**客户端**：`MonPanel` 在当前技能旁显示「更换」、空槽显示「学习新技能」，选择后发 `mon_replace`，等 `mon_data` 再刷新；没有 `learnable` 时不显示入口。`BattleUi` 出招菜单显示属性 / 物理特殊 / 威力 / 命中 / PP / 克制，对手显示 `hp/max`，战斗结束显示结算摘要，增加快进（`localStorage`）。
**服务端**：本地已实现（私有服务端仓库 `develop`）：`mon_data` 带 `learnableMap()`、`mon_replace` 走共享 `learnMove()`，`run()` 的战斗保护会拒绝战斗中更换；**测试服已部署（2026-11-10），正式服待部署**。
